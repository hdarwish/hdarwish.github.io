The lock-in was never the weights. It was the name.

Somewhere in your repo there is a line that looks like AutoModel.from_pretrained("bert-base-uncased"). One string. No version, no hash, no hostname, no vendor. It resolves at build time, over the network, unauthenticated, through a registry run by a private company — and Business Insider reports that company has been in talks to be bought for more than $13 billion by Nvidia, which also sells you the GPU the thing will run on.

You have probably been telling yourself: open weights mean I'm safe. The tensors are Apache-2.0, the tokenizer is a JSON file, the whole thing is a few hundred megabytes sitting in a cache directory. Worst case you download it once and walk away. That story is true about the artifact and completely false about the path you take to get it — and the path is the part that runs again every time a container comes up cold.

Portability of weights is not portability of resolution.

So follow the string. "bert-base-uncased" is not a file and not a URL. It's a coordinate in a namespace: an implied org (the canonical one), a repo name, and — critically — an unstated revision, which by default means whatever the branch tip happens to point at right now. The library takes that coordinate, asks the Hub's API which files exist and where they live, and pulls them into a local cache keyed by what it just learned. Three separate things get decided for you inside that one call: which repo the bare name means, which commit "latest" means, and which files count as the model. You specified none of them, and you cannot audit any of them from the call site.

DNS is the honest analogy, and it's honest in both directions. You type a name; a system you don't operate maps it to bytes; if the mapping changes, you change with it, silently, and your code reads identically before and after. Where the analogy breaks is the direction that should worry you: DNS has a root, many independent operators, a contentious but genuinely multi-stakeholder governance process, and four decades of paranoid tooling built on the assumption that names are attack surface. Model-name resolution has none of that. Model-name resolution has a cap table.

Now run the thought experiment I keep circling back to. Imagine you own the registry and you want to change what a million developers actually execute — without touching a single weight, without breaking a single API, without anyone filing an issue. You don't need the weights. You own the canonical namespace, so you decide what a bare name means. You own search ranking and the model cards, so you decide what "the obvious choice" is in the next hundred thousand tutorials. You decide which quantizations and which hardware-optimized variants sit at the top of the page. You set rate limits on unauthenticated pulls, which means you set the price of continuing to do this the naive way. You control deprecation, redirection, and what a moved repo hands back. None of that requires malice. It requires a roadmap.

And the entity holding those levers is being folded into the company that sells the accelerator. Discovery and silicon on one org chart: the place developers go to find out what to run, owned by the vendor whose margin depends on what they run it on.

I want to be exact here, because the temptation to shout is strong and shouting makes you stupid. I am not predicting Nvidia will degrade anything. I have no idea what they'll do, and they may turn out to be excellent stewards — they have shipped a great deal of genuinely open tooling. What would change my mind is a credible externally-governed root for model names, or a resolution scheme a client can verify without trusting the registry at all. Neither exists today. Until one does, the question "will they behave well?" only becomes interesting after you've already handed someone the switch. Good behavior is not an architecture.

The lock-in was never the weights. It's that a bare model name resolves through a namespace you don't own, in CI, unauthenticated, at build time.

Sit with that.

Your dependency graph is bigger than your lockfile claims. You pinned your Python packages to exact versions and hashes like a responsible adult, ran a scanner over them, argued about the diff in review — and then, three functions into your inference service, you left a naked string that reaches out to a third party's ranking decisions every time a cold container wakes up. You have already built this machine. Probably in several services at once. Your model-loading code has a vendor's business strategy in the call stack.

The remedy is unglamorous and available this afternoon. Pin revisions to commit SHAs instead of branch names — the libraries take a revision argument and almost nobody passes it. Mirror the artifacts into storage you control and point at that, so the registry becomes a source you sync from rather than a dependency you call. Turn off network fetches in CI, so a build that would have silently re-downloaded a moved model fails loudly instead of succeeding differently. Prefer formats that don't execute code on load. Treat it exactly as you'd treat any other supply-chain dependency, because that is precisely what it is — and the $13 billion figure is just the market pricing that fact in ahead of you.

The portable idea is larger than one hub: go find every place your system resolves a name you don't own. Container tags. Base images. Package registries. Model IDs. Cloud endpoint hostnames. Each one is a default, and a default is not neutral infrastructure — it's a rented position, and rent gets renegotiated. Defaults always have an owner, and the owner's interests are aligned with yours only by coincidence.

The weights were always free. The name never was. Write the SHA down.
