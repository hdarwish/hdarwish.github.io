The 'Don't Ask Again' button is a security hole

1,122 public GitHub repositories now contain exposed passwords, not because of a sophisticated hacker, but because an AI assistant asked for permission to read a file and the user clicked 'Don't Ask Again' without thinking.

securityai-codinghuman-factorsgithub

Security controls must be friction; if they are frictionless, they are invisible, and if they are invisible, they are gone.

The distinctionThe difference between a security control that forces a decision and a UI convenience feature that removes the decision.

01

The Friction Was the Point

Every time your operating system asks for a password, it is annoying you. That annoyance is not a bug; it is the mechanism. It is a tax you pay for the privilege of accessing sensitive resources, and it is the only thing standing between your habits and a catastrophic failure. When you click "Yes" to a permission prompt, you are engaging in a micro-transaction of attention. You are acknowledging that something is happening that requires your consent.

Now, imagine a tool that says, "I will do this, but I don't want to annoy you. I will remember that you said yes, so I never have to ask again." You click it. You feel efficient. You feel smart. You have just disabled the only line of defense against your own future carelessness. This is not a metaphor. This is exactly what happened when 1,122 public GitHub repositories started leaking passwords.

02

The 1,122-File Failure

The incident involving Claude Code and the "Don't Ask Again" feature is a perfect storm of human psychology and software design. The AI coding tool needed to read files to perform its tasks. To do this, it required permission. The user, tired of clicking "Allow" every time the agent needed to access a new directory or file, selected the option to suppress future prompts for that specific type of action.

The metric here is not latency or throughput; it is exposure. The consequence was that the agent, now free from the friction of permission checks, began reading files it should never have read. It found environment variables containing secrets. It found configuration files with API keys. And because the agent was operating in a context where those secrets were treated as normal data, they ended up in the codebase. That codebase was public. The secrets were in 1,122 files. The friction was the filter, and by removing it, you removed the filter.

03

Convenience as a Vector

We treat "Don't Ask Again" as a quality-of-life feature. It is, in fact, a security vulnerability. It is a vector for error. When a system removes a decision point, it does not just save you time; it removes your ability to notice when the system is doing something wrong. The prompt was not just an interruption; it was a checkpoint. It was the moment where you could say, "Wait, why is the agent looking in the .env directory?"

By clicking "Don't Ask Again," you delegated that vigilance to the tool. And the tool, being an AI, does not have the concept of "sensitive." It has the concept of "accessible." If a file is accessible, and you have told the tool that it is always okay to access it, the tool will access it. It will read the secret. It will write the secret. It will commit the secret. The mechanism is simple: permission persistence removes the human-in-the-loop, and the human-in-the-loop is the only thing that understands context.

04

The Last Line of Defense

The most dangerous security flaw in modern AI coding tools is not prompt injection. It is not model hallucination. It is the UI convenience feature that silently disables the last line of defense against human error. We are building tools that are faster than our attention spans, and we are rewarding speed by removing the checks that keep us honest. The result is a world where a single click, made in a moment of fatigue or convenience, can expose every secret in your organization.

The turn

The "Don't Ask Again" button is not a feature. It is a resignation. It is the user resigning their right to be surprised, and in doing so, they resign their responsibility for the outcome.

Analogy It is like telling your home alarm system to never beep again. The beep is annoying, but the beep is the only thing that tells you the door is open. If you silence it, you can sleep through the break-in.

Where it breaks The alarm doesn't read the files. The AI agent does. The alarm is a passive signal; the agent is an active actor. The analogy holds for the removal of the signal, but the agent's action is more complex than a door opening.

If you're deciding
When
You are using an AI coding assistant that asks for file access permissions.
Prefer
Keep the prompts. Treat every permission request as a potential security event. Audit what the agent is accessing.
Avoid
Clicking "Don't Ask Again" for broad file access categories. Never suppress prompts for directories containing secrets, configuration, or environment files.

Friction is not the enemy of security. Friction is security. The moment you remove it, you are not saving time. You are saving your future self from having to explain why the database is public.
