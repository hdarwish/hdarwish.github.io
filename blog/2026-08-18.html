Your autofix bot is an attacker you gave commit rights to

On June 18, 2026, a commit landed in snowflakedb/snowflake-connector-net that took a safe pattern out of a CI workflow and put an injectable one in its place. The squash commit credits a co-author: Copilot Autofix powered by AI. Five days later an autonomous agent from Wiz Research opened a GitHub issue with a carefully chosen title and walked out with a Jira API token that authenticated as qa@snowflake.net against Snowflake's internal Atlassian instance.

The review on that pull request said it was fine.

You have almost certainly installed at least one bot with write access to your repositories, and you judge its output on a criterion that has nothing to do with security: whether it looks like a fix. Attacker-controlled data that arrives formatted as a diff, labeled remediation, and co-signed by a security tool trips none of the reflexes you built for handling untrusted input. That is the vulnerability class. Everything below is one very good example of it.

The mechanism is beautiful the way plane crashes are beautiful — three independent things had to be true at once, and all three were.

The original workflow did the correct thing. It passed the issue title into an environment variable and handed that variable to jq:

env:
  ISSUE_TITLE: ${{ github.event.issue.title }}
run: jq -n --arg title "$ISSUE_TITLE" ...

This is the pattern GitHub tells you to use, and it works for one precise structural reason: ${{ }} expansion happens before the shell ever exists. The runner does textual substitution into a script file, then bash is handed the file and runs it. Put the title in an env: block and it arrives as a real environment variable, which the shell treats as opaque bytes. Interpolate it into the run: body and you are not passing a string at all — you are editing the program before the interpreter starts.

The new version edited the program:

run: TITLE=$(echo '${{ github.event.issue.title }}' | sed 's/"/\\"/g' ...)

Look at that sed. It is trying. It escapes double quotes, which is a real defense against a real attack — just not this one, because the string is wrapped in single quotes, and it runs after expansion, inside a script the attacker has already rewritten. One apostrophe in an issue title closes the echo '...' and everything after it is your code now. Sanitization applied one layer too late isn't sanitization. It's upholstery.

Then there was the gate, which looked at a glance like access control:

if: (github.event_name == 'issues' && github.event.pull_request.user.login != 'whitesource-for-github-com[bot]')

On an issues event, github.event.pull_request is null. The second clause therefore evaluates null != 'whitesource-for-github-com[bot]' — true, permanently, for every human and bot alive. The gate was a door frame with no door in it. And the trigger was issues: opened, which means the bell was mounted on the public street.

The exploitation is my favorite part, because it is where the scanner stops scanning and starts behaving like an adversary. Red Agent's first payload used # to comment out the rest of the line — the standard move, and wrong here, because the # also swallowed the closing ) of TITLE=$(...) and bash died with unexpected EOF. The agent read that syntax error, worked out why its own payload had broken the enclosing command substitution, and rewrote the injection to close the shell block cleanly with ; echo '. Then curl fired from an Azure runner IP, base64-encoding $JIRA_API_TOKEN, $JIRA_USER_EMAIL, and $JIRA_BASE_URL into a query string.

Nobody drove that. The debugging loop belonged to the machine.

The tempting reading is: AI wrote a bug, AI review missed it, AI found it, three AIs walk into a CI runner. Cute, and it misses the shape completely. Ask instead what an autofix bot is, structurally, inside your pipeline. It reads untrusted material — issue text, scanner findings, dependency metadata, code from strangers. It transforms that material through a process you cannot audit. It emits into your repository a text blob that becomes executable on merge. Every property that defines untrusted input is satisfied. The only missing thing is the label, and the label is missing because the output has the shape of help.

Nor is this a Copilot problem. It is the shape of every remediation bot, every Dependabot-style rule, every "agent that opens a PR," every ticket-to-patch pipeline wired up by someone who was tired of triaging CVEs by hand. They all read hostile data at one end and hold write access at the other.

An autofix bot is an attacker with commit rights that you installed on purpose.

Sit with that a moment, then take the analogy — and I'll show you where it snaps. A CI workflow is a restaurant kitchen and untrusted input is a delivery from a supplier nobody vetted. The env: pattern is receiving the crate at the back door: it goes in a labeled bin, you decide what to do with it, it never touches the recipe card. The interpolation pattern hands the supplier a pen and lets him rewrite the recipe. The snap comes here: a real head chef would notice a recipe that says "add curl." A reviewer looking at a diff titled autofix would not, because humans do not read a fix the way they read an attack. The analogy breaks exactly where trust in the author replaces inspection of the artifact. That substitution is the actual exploit.

So the portable rule: classify your automation by what it reads, not by what it's for. A bot that ingests attacker-reachable text sits on the untrusted side of your boundary no matter how many times the word "security" appears in its name, and the review it needs is not "does this look like a fix" but the paranoid squint you'd give a PR from a two-hour-old account — backed by defenses that don't depend on squinting at all. No secrets in workflows reachable by issues: opened. Expansion-versus-execution ordering as a first-class rule you can recite. And every if: gate tested against a null, because a condition you have never seen fail is a condition you have never tested.

Snowflake fixed it the day it was reported, rotated the credential, and showed from audit logs that Wiz was the only actor in the window. That is a genuinely good outcome, and it happened because a human could still read the logs, still turn a key, still reconstruct who touched what.

Keep that ability close. The machines are getting very fast at writing things that look like help.
