Your AI is lying about who you are

Claude Code is broadcasting your email address to strangers in the User-Agent header. The leak is a symptom; the trust model is the disease.

ai-securityprivacyagentic-aiclaude-code

We treat AI agents as trusted extensions of our identity, but they operate with our credentials without our consent.

The distinctionA tool executes a command; an agent makes a decision. We built the security model for the first and deployed the second.

01

The Silent Introduction

Your AI assistant just introduced itself to a third-party website using your real email address, and you didn't even know it was talking. This isn't a hypothetical. A GitHub issue titled "Privacy violation in User-Agent header" describes how claude code divulges user emails to arbitrary third parties while conducting web searches. The reporter, Taylor Edwards, notes receiving "dozens of scam emails per day" as a direct result. The data didn't leak from a database. It leaked from a handshake.

The mechanism is mundane, which is what makes it terrifying. When an HTTP request is made, the User-Agent header identifies the client. Standard practice for browsers is to identify the software version. claude code went a step further: it appended the user's authenticated email address to that header. To the receiving server, the request didn't look like it came from "Claude Code v1.2." It looked like it came from "Claude Code, on behalf of taylor@example.com."

This is not a bug in the traditional sense. It is a feature of a trust model that assumes the agent is a perfect proxy for the user. The agent is granted the key to your identity, and it uses that key to knock on every door it encounters.

02

The Identity Leak

Let's look at the mechanism. The User-Agent string is sent with every request. If the agent performs 100 web searches, it sends your email to 100 different servers. These servers are not necessarily malicious; they are logging infrastructure, analytics tools, and third-party APIs. But the metric here is exposure surface. By embedding identity in the header, the agent turns every API call into a PII disclosure event.

The consequence is immediate and irreversible. Once an email address is in a third-party log, it is out of your control. It can be scraped, sold, or used for targeted phishing. The reporter’s experience of "dozens of scam emails" is the downstream effect of a single, silent header field. The agent didn't send an email; it just told everyone who it was talking to.

03

The Consent Gap

The real failure isn't the code. It's the implicit trust. We grant autonomous agents our identity because we need them to act on our behalf. But we haven't built a consent layer for that identity. When you type a command into a CLI, you are not explicitly authorizing the transmission of your PII to every host the agent touches. You are authorizing the task. The agent is conflating the two.

This is the distinction that matters: a tool executes a command; an agent makes a decision. A curl command is a tool. It sends what you tell it to send. An agent is a decision-maker. It decides *how* to send it, *where* to send it, and *what* to include. We have deployed decision-makers with the permissions of tools and the opacity of black boxes.

The turn

The security failure is not that data leaked. It is that we allowed a machine to speak with our voice without a microphone check. We handed the agent our name and let it go out into the world, assuming it would know when to be quiet.

Analogy It's like hiring a personal assistant and giving them your house key, your bank card, and your phone, then expecting them not to accidentally leave your credit card at the bar when they go to order a pizza.

Where it breaks The assistant is intelligent and careful; the agent is probabilistic and fast. The agent doesn't 'forget' to include the email; it includes it because the code path says so. The analogy breaks on intent.

If you're deciding
When
You grant an autonomous agent access to your authenticated identity
Prefer
Explicit, per-domain consent for PII transmission; audit logs for all external requests
Avoid
Assuming the agent will respect privacy boundaries you haven't explicitly defined

Until we build consent into the agent's bones, we are not using a tool. We are leaking a self.
