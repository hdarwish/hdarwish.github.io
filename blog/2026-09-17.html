Let the LLM Testify, Not Judge

An LLM can improve a classification system while being a worse classifier than the system built around it.

That sounds contradictory only if you assume the model’s verdict is its most valuable output. Often it is not. The valuable part is its ability to notice evidence buried in unruly language: a complaint describing coercion without naming it, a message implying cancellation without using the word, a contract hiding an exception inside otherwise ordinary prose. The LLM may detect those clues brilliantly and still combine them into a badly calibrated decision.

Fluency is not measurement

Picture a service deciding which cases deserve human review. If the LLM returns only a hard label, the useful uncertainty has already been crushed: you cannot cleanly choose a threshold that favors recall today and precision tomorrow. Token log probabilities are available in some systems, but they should not be mistaken for calibrated class probabilities without validation. Asking the model how confident it feels is worse; that produces another fluent sentence, not a trustworthy measuring device.

A confident verdict is not a calibrated score.

The distinction matters because a final label contains policy, whether you acknowledge it or not. Which errors are expensive? How common is the positive class in this population? How much review capacity exists? A prompt can recite those facts, but the model does not have to use them consistently—or at all—so the precision-recall trade-off becomes entangled with prose whose operational meaning cannot be inspected, estimated, or adjusted directly.

Convert the verdict into evidence

Suppose the LLM emits a binary signal, LLM(x), indicating whether it found a relevant pattern. Instead of accepting that signal as the decision, feed it into an ordinary logistic regression:

p(y = 1 | x) = sigmoid(alpha + beta * LLM(x))

If the outer model is forced to copy the LLM, you have merely added decorative mathematics around the original verdict. Estimate alpha and beta from labeled examples instead, and the system learns how much the observation deserves to count in the population you actually care about. If the signal predicts the label strongly, it receives weight. If it is weak, reversed, or useless, the fitted model can reveal that too.

With one binary LLM feature, the model has only two groups to understand: examples where the LLM said yes and examples where it said no. An unregularized fit, when the data are not completely separated, corresponds to estimating a positive rate for each group. The output is now an estimated probability rather than an inscrutable command, so you can evaluate calibration and discrimination separately, then select an operating threshold according to precision, recall, cost, and review load.

The LLM has become a witness rather than the judge.

This resembles replacing an oracle with a laboratory instrument. The instrument may detect something ordinary tools miss, but a separate process interprets its reading using standards that can be checked and changed. The analogy has a sharp limit: an LLM is not physically stable like a thermometer. Change the prompt, model version, or input distribution and you may have changed the instrument itself—which is exactly why its output must be measured downstream rather than granted authority upstream.

Give the rest of the evidence a vote

Once the LLM output is merely a feature, structured covariates can enter without being translated into a polite paragraph and offered to the model in the hope that it pays attention. Account state, document type, source population, and other available signals can be combined directly with the semantic feature. The outer classifier can estimate interactions, respond to baseline prevalence in the training data, and expose whether the LLM’s observation adds discrimination beyond what the structured variables already provide.

Different target population? Reweight or refit on representative data. Different tolerance for false positives? Move the threshold. Suspect the LLM signal fails for a subgroup? Measure calibration and error rates there. Each question has a corresponding metric and an explicit engineering control; none requires bargaining with a prompt as though it were a minor woodland deity.

The same framing makes iteration less superstitious. When the LLM owns the verdict, disappointing performance invites prompt fiddling: change the wording, rerun the evaluation, squint at the aggregate score, repeat until morale improves. When the model produces named observations instead, residual errors can reveal which evidence is missing. You can request several distinct signals, test token probabilities as additional inputs, inspect whether each feature predicts the intended target, and discard features that merely sound intelligent.

Feature engineering gives failure somewhere to stand.

Policy belongs outside the prose

Once you separate the component that reads slippery language from the component that must respect prevalence, asymmetric costs, operating thresholds, subgroup behavior, and finite review capacity, an architectural fact becomes impossible to ignore: asking one generative model to perform both jobs does not simplify the system; it hides the decision rule inside a mechanism you cannot properly tune.

LLMs should supply evidence, not own the classification decision.

This is larger than a modeling preference. It is a boundary between perception and policy. The LLM handles the part at which it is unusually useful—extracting semantic clues from text—while the outer system handles the part that must remain measurable: combining evidence, estimating probabilities, choosing thresholds, and changing behavior when costs or populations change.

The price is labeled data, which punctures the charming fantasy of a training-free classifier. Good. A consequential classification system already needs representative evaluation data if you intend to know whether it works. Fitting and calibrating a small outer model is not bureaucratic backsliding; it is admitting that performance claims require evidence, and that a test set cannot rescue a decision rule whose policy remains trapped inside a prompt.

So replace the seductive question, “Can the LLM decide this?” with the more useful one: “What can the LLM observe here that my existing features cannot express?” Name that observation, validate it as a target, measure its stability, combine it with the rest of the evidence, and keep the operating threshold somewhere humans can inspect and alter.

Let the strange machine read the fog. Keep the steering wheel.
