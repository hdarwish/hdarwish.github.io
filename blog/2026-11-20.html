The most effective spam filter is a human in the rain

We spent decades building algorithms to stop spam. The only thing that actually worked was making the target too expensive to reach.

local-firstsecurityspamhardware

Spam is an economics problem, not a security problem. It persists because the cost of sending a message is near zero while the cost of ignoring it is low.

The distinctionThe difference between a *filter* (which tries to identify bad actors) and a *barrier* (which raises the cost of action for everyone).

01

The Algorithm Illusion

Spam hasn’t been solved by better machine learning. It hasn’t been solved by IP reputation scores, DKIM signatures, or neural network classifiers. It has been solved, in the places that actually matter, by making the target *expensive* to reach.

Think about email. The most effective anti-spam measure isn’t the filter in your inbox; it’s the fact that sending an email to a stranger requires you to know their address. That friction is the barrier. The filter is just cleanup for when the barrier fails.

02

The Garage Door as a Spam Target

Harrison’s story is a perfect case study. Chamberlain’s myQ app was encrusted with ads, but the notifications were meaningful. Then, in late 2023, Chamberlain cut off third-party API access. Harrison’s response? He bought two ratgdo32 boards for $62 each.

These devices run locally on his network, speak LiftMaster’s Security+ 2.0 protocol, and expose a JSON status endpoint. No cloud. No ads. No third-party API dependencies. Just a $62 board that talks to his garage door over his own WiFi.

03

The Barrier Is the Human

Here’s the key insight: the ratgdo32 doesn’t *filter* spam. It doesn’t try to identify malicious actors. It simply makes the target *local*. To interact with the door, you have to be on Harrison’s network. You have to know the IP address. You have to speak the protocol.

That’s the barrier. The cost of action has been raised from 'send an HTTP request to a public API' to 'physically access the local network and reverse-engineer a proprietary protocol.' The spam filter isn’t an algorithm. It’s the fact that you have to be *there*.

The turn

The most effective spam filter isn’t a firewall or an IP block. It’s the physical reality that a human has to stand in the rain to open the door.

Analogy A garage door is like a private house. You don’t need a bouncer at the door if the house is in a neighborhood where everyone knows each other and the address isn’t published.

Where it breaks This breaks down if the 'neighborhood' becomes public, or if the 'address' is leaked. Local-first security relies on the obscurity of the access path, which is a weak assumption in large-scale systems.

If you're deciding
When
You’re building a system that exposes a public API or cloud endpoint
Prefer
Local-first architecture with explicit, high-friction access patterns
Avoid
Assuming that authentication or rate-limiting is a sufficient barrier

The next time you’re designing a system, ask yourself: what’s the most expensive thing about reaching this target? If the answer is 'nothing,' you’ve built a spam target.
