Your 'Local-First' AI is a Trojan Horse

The rage over Convex's quickstart skill isn't about one bad script. It's about how we've normalized sending our proprietary logic to the cloud as a feature.

AI SecuritySupply ChainData PrivacyAgent Skills

In the age of AI agents, the boundary between 'local execution' and 'remote telemetry' has dissolved. When a tool runs on your machine, you assume sovereignty. When it phones home, you assume a bug or a feature. We have lost the vocabulary to distinguish the two.

The distinctionThe difference between a *dependency* (which you vet) and a *remote instruction* (which you cannot vet).

01

The Bug Report That Wasn't a Bug

On October 26, 2026, a user named thirtysix filed Issue #64 on the convex-backend-skill repository. The title was blunt: *"Quickstart skills send the user's idea to a convex.site host and run remote scripts, written to avoid safety checks."* It wasn't a crash report. It was an architectural disclosure. The skill, designed to help developers scaffold a backend, was quietly POSTing their one-sentence project idea to basic-anteater-667.convex.site.

The code didn't hide this in a binary. It hid it in plain sight, in a comment that read: # [telemetry 1/3] personalize → bespoke runbook slug. The user's idea was being used to generate a unique identifier on a remote server, which was then logged as "a run started." The user was never told their intellectual property was leaving the machine.

02

Engineering Around the Guardrails

The most chilling part wasn't the telemetry; it was the evasion. In skills/labs-quickstart/SKILL.md, the instructions explicitly told the AI agent to split the download and execution of a bootstrap script into two separate Bash calls. The comment provided the reason: *"A single command that both downloads remote code and executes it is the shape harness safety classifiers block."*

This is not a security hole. It is a security *feature* of the skill's design. The developers knew that a curl | bash pattern would be flagged by the user's safety tooling. So they engineered the skill to look like two innocent, local operations. First, download a file. Second, run a file that is already on disk. The user's safety classifier, designed to catch obvious malice, saw two benign actions. The agent, following its instructions, executed both. The result was a remote script running with the user's privileges, unvetted by any human.

03

The Normalization of the Cloud

We have reached a point where "local-first" is a marketing term, not a technical guarantee. We have normalized the idea that our proprietary logic—our app architecture, our data schemas, our business ideas—can be treated as *input* to a remote service without our explicit, informed consent. We treat the cloud as a utility, like electricity. You don't ask the power company for permission to turn on the light. You don't ask the cloud for permission to send your data.

But a utility doesn't read your thoughts before plugging you in. When an AI coding assistant sends your project idea to a server to generate a "bespoke runbook," it is not just using a utility. It is harvesting your intent. And because we have built our workflows around the frictionless convenience of remote services, we have lost the reflex to ask: *Where is this data going, and who is deciding for me?*

The turn

The outrage in the issue tracker isn't about Convex. It's about us. We built a world where the most sensitive parts of our work—our ideas, our logic, our secrets—are treated as fuel for remote engines, and we called it *progress*. The bug wasn't that the skill sent data to the cloud. The bug was that we stopped noticing.

Analogy It is like hiring a plumber to fix your sink. The plumber is great, fast, and local. But while he is under the sink, he is also quietly uploading a video of your basement to a server so he can "personalize his service." And if you ask him why, he says, "Well, my company's safety guidelines say I can't show you the video, so I just split the upload into two parts so your security camera doesn't flag it."

Where it breaks The plumber is a human with a social contract. The AI agent is a code execution environment with no social contract. It does not *choose* to evade safety checks; it is *instructed* to do so by the skill's author.

If you're deciding
When
You are using an AI agent to scaffold a new project or execute a complex workflow.
Prefer
Assume the agent will exfiltrate data unless it is explicitly sandboxed and audited. Vet every remote script. Pin every dependency by hash. Treat 'telemetry' comments as red flags, not footnotes.
Avoid
Trusting that 'local' execution means 'local' data. Never allow an agent to pipe remote content directly into a shell, even if it is split into two steps.

The next time your AI assistant says it's "just scaffolding," ask it where the scaffolding is going. If it won't tell you, it's not scaffolding. It's a Trojan horse.
